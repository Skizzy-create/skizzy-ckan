# skizzy-ckan

CKAN metadata repository for [Skizzy Naval](https://github.com/Skizzy-create/skizzy-naval):
naval and combat mod builds for **KSP 1.12.5 + BDArmory Plus 1.13**.

## Add it to CKAN

CKAN > *Settings* > *Metadata repositories* > *New*. Name: `SkizzyNaval`. URL:

```
https://github.com/Skizzy-create/skizzy-ckan/archive/refs/heads/main.tar.gz
```

Keep the default `KSP-default` repository as well, because ModuleManager, BDArmory Plus and the
other dependencies come from it. After a refresh, install **Skizzy Naval Pack**
(`SkizzyNavalPack`), or single modules:

| Identifier | What it is |
|---|---|
| `SkizzyNavalPack` | Metapackage: all modules below, plus ModuleManager and BDArmory Plus 1.13 |
| `SkizzyNaval-HullBreach` | HullBreach 1.8 port (flooding, crush depth) |
| `SkizzyNaval-NAS` | NAS 0.7.0 updated (WWII guns, torpedoes, depth charges) |
| `SkizzyNaval-LargeBoatPartsPack` | Large Boat Parts Pack updated |
| `SkizzyNaval-MaritimePack` | Fengist's Maritime Pack updated |
| `SkizzyNaval-AdvancedWeaponsPack` | Advanced Weapons Pack updated |
| `SkizzyNaval-MNWS` | [MNWS] Modern Naval Weapon System 2.4 updated |
| `SkizzyNaval-IronSeasKANES` | Iron Seas Balao-class submarine updated |
| `SkizzyNaval-AircraftCarrierAccessories` | Patch for Aircraft Carrier Accessories (installs the original) |
| `SkizzyNaval-FishyWeapons` | Patch for Fishy Weapons (installs the original) |
| `SkizzyNaval-TitansBDArmoryExtension` | Patch for TBAE (the original must be installed by hand) |
| `BDArmory-Skizzy` | Optional BDArmory Plus 1.13.1 build with the Skizzy fork plugin (replaces BDArmory) |
| `SubTrim` | Automatic submarine trim and depth hold ([Skizzy-create/SubTrim](https://github.com/Skizzy-create/SubTrim)) |

Licences and changes for each module are listed in
[skizzy-naval's README](https://github.com/Skizzy-create/skizzy-naval#modules-and-licence-decisions).

## How the files get here

Do not edit the `.ckan` files by hand. They are generated by skizzy-naval's release workflow
from `registry.toml` and the real release assets (sizes and SHA-1/SHA-256 hashes). The
workflow pushes them here, or opens a pull request. Each identifier has its own folder,
`<identifier>/<identifier>-<version>.ckan`. Older versions stay, so CKAN can still offer
them.

## Validation

`.github/workflows/validate.yml` runs `scripts/validate.py` on every push and pull request. It
checks:

- the JSON against the vendored `schema/CKAN.schema` and against the latest upstream schema;
- file naming and duplicate versions;
- that the `spec_version` covers the features used (`any_of` needs v1.26);
- hash formats;
- that every relationship to one of our own identifiers resolves to a file here.

On pull requests it also downloads every changed file and compares its size and hashes.

```sh
pip install -r scripts/requirements.txt
python scripts/validate.py                    # schema and consistency checks
python scripts/validate.py --check-downloads  # also download and hash every file
```
